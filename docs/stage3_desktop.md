Расположение кода: `app/lib/platform/`, `app/lib/state/`, `app/lib/ui/`, изменения ядра — `app/lib/core/` и `app/lib/data/`.
Ядро этапа 1: `docs/core_modules.md`. Итоги и открытые вопросы этапа 1: `docs/stage1_report.md`. Этап 2 (Android): `docs/stage2_android.md`. Общая архитектура: `docs/architecture.md`.

> **Статус:** этап перенесён — сначала Android (`docs/stage2_android.md`), desktop — этап 3. Решения 1.1–1.10 подтверждены; решение 1.11 (песочница macOS) и вопрос App Store отложены до этапа публикации.
>

## 0. Цель этапа 3

Рабочее desktop-приложение (Windows, macOS и Linux): пользователь выбирает папки, нажимает кнопку, видит план, применяет его и может всё откатить — на реальных файлах.

**Входит в этап:**
- изменения ядра, отложенные с этапа 1 (типизированные коды причин и ошибок, расположение источника, отмена хеширования) и первая миграция БД;
- desktop-адаптер `FileSource` на `dart:io` и FFI;
- платформенные службы: часы, идентификаторы, файл БД, защита от второго экземпляра приложения;
- слой состояния на Riverpod;
- локализация ru / en;
- UI: онбординг, главный экран, прогресс, план, результат и откат, история, настройки;
- интеграционные и нагрузочные тесты, CI на Linux, Windows и macOS, сборки под все три ОС.

**Не входит в этап:** нативный код Android / iOS, ИИ и бэкенд, подписка, уборка по расписанию, автозапуск и трей, автообновление, подпись сборок, поиск похожих фото, сетевые диски (см. 1.6).

**Результат этапа:** на реальной папке проходит полный цикл «онбординг → кнопка → план → выполнение → откат», контрактные тесты `FileSource` проходят против desktop-адаптера на реальной ФС под Linux, Windows и macOS, все инварианты ядра сохраняются.

## 1. Решения, требующие подтверждения

| # | Вопрос | Предложение | Почему |
|---|---|---|---|
| 1.1 | Целевые ОС этапа | Windows, macOS и Linux — поддерживаются и тестируются: CI на трёх ОС, ручной чек-лист на Windows и на Mac пользователя | Windows — по плану архитектуры, Linux — машина разработки, Mac для проверки есть |

Проверка перед переименованием оставляет окно гонки — нарушение инварианта 1 |
| 1.3 | Тексты причин и ошибок | Типизированные коды с параметрами в ядре и журнале; тексты — только в локализации UI | Сейчас это английские строки внутри ядра; менять модель дешевле до появления UI |
| 1.4 | Названия папок шаблона | Выбираются один раз при первом запуске (по языку системы) и хранятся в настройках; смена языка интерфейса их не меняет | Иначе после смены языка появится второй комплект папок («Документы» и «Documents») |
| 1.5 | Где хранить карантин | Скрытая папка `.file-organizer/` в корне каждого источника | Тот же диск (перемещение мгновенное, без копирования), есть права записи; папка уже исключена из уборки (`appFolders` и правило скрытых папок) |
| 1.6 | Сетевые и облачные папки | Сетевые диски не поддерживаются: источник на них не добавляется. Облачные заглушки (OneDrive / iCloud «файлы по запросу») не хешируются и не перемещаются | Хеширование заглушки скачивает файл из облака; поведение переименования на сетевых ФС не гарантировано |
| 1.7 | Символические ссылки, junction-точки, другие тома внутри источника | Не используются: ссылки не попадают в листинг, папки-ссылки и папки на другом томе не обходятся и попадают в «недоступные» | Ссылка может вести за пределы источника; перемещение между томами — это не атомарное переименование |
| 1.8 | Дата съёмки фото | Читать EXIF `DateTimeOriginal` у JPEG при листинге (только первые 64 КБ файла); HEIC и видео — позже | Скопированные на компьютер фото получают новую дату изменения и иначе попадут не в тот год |
| 1.9 | Хеш-функция | SHA-256 (пакет `crypto`), значение с префиксом алгоритма (`sha256:…`) | Надёжный и проверенный; префикс позволяет сменить алгоритм позже без ложных совпадений |
| 1.10 | Вложенные источники | Запрещены: папку нельзя добавить, если она внутри другого источника или содержит его | Иначе один файл окажется в двух индексах и двух планах |
| 1.11 | Песочница macOS (App Sandbox) | **Требует подтверждения.** В этапе 2 отключить песочницу (распространение вне App Store, с нотаризацией в этапе 5). Права ОС на «Рабочий стол», «Документы», «Загрузки» (запросы TCC) обрабатываются как `permissionDenied` с подсказкой в UI | В песочнице доступ к выбранной папке после перезапуска требует security-scoped bookmark вместо пути, а сканирование вне выбранных папок невозможно. Если позже понадобится App Store — `Source.location` уже непрозрачная строка и вместит закладку |

## 2. Принципы этапа

1. **Инварианты ядра не ослабляются.** Адаптер — первый код, который трогает реальные файлы; любое сомнение — в сторону «не трогать».
2. **Адаптер без бизнес-логики.** Он только переводит пути и выполняет вызовы ОС; решения принимает ядро.
3. **Никакой перезаписи на уровне ОС.** Перемещение и восстановление — только вызовом, который сам отказывает, если цель занята (1.2). Копирование между томами не выполняется никогда.
4. **Единственное удаление** — `purgeQuarantined`, и только внутри папки карантина, по проверенной ссылке.
5. **Всё внутри источника.** Логический путь не может выйти за корень; ссылки и другие тома не обходятся (1.7).
6. **UI не трогает данные напрямую**: только через слой состояния (`ui → state → core ← data / platform`); правило проверяет архитектурный тест.
7. **Один экземпляр приложения.** Второй экземпляр не запускает уборку (5.3).

## 3. Изменения ядра и данных

Все изменения порта и модели — с обновлением `docs/core_modules.md` и контрактных тестов.

### 3.1. Типизированные коды причин и ошибок (1.3)

- `Classification.reason` — тот же подход.
- Тексты формирует только UI через локализацию.

### 3.2. Расположение источника
- `Source.location` — непрозрачная строка адаптера: для desktop — абсолютный путь к корню папки (для Android позже — URI, для iOS — закладка). Ядро её не разбирает.

### 3.3. Настройки
- `Settings.layoutFolderNames` — названия папок шаблона, фиксируются при первом запуске (1.4).
- `Settings.uiLocale` — язык интерфейса (пусто — язык системы).

### 3.4. Отмена хеширования
- `FileSource.partialHash` / `fullHash` получают необязательный `CancelToken` (новый тип в `core/ports`); адаптер проверяет его между блоками чтения и возвращает новый вид ошибки `cancelled`. `DuplicateFinder` передаёт токен, `workflow.cancel()` его взводит.

### 3.5. Миграция БД (схема версии 2)
- Первая настоящая миграция: новые колонки и таблицы для 3.1–3.3. Старые текстовые причины переносятся как код `legacy` с исходным текстом.
- `dart run drift_dev make-migrations` генерирует тесты миграции v1 → v2 в `test/data/migrations/`; они обязательны.

## 4. Desktop-адаптер `FileSource` (`lib/platform/desktop/`)

### 4.1. Источник и пути
- Корень — `Source.location` (абсолютный путь). Логический путь → реальный: корень + сегменты через разделитель ОС. Реальный → логический: относительный путь, разделитель → `/`.
- Windows: пути длиннее 240 символов передаются с префиксом `\\?\` во все вызовы `dart:io` и FFI.
- Имя файла возвращается в фактическом написании (регистр, нормализация Unicode) — так, как его вернула ОС.
- При открытии адаптер проверяет: корень существует и это папка; корень не на сетевом диске (1.6); права записи; поддержку переименования без перезаписи (пробная операция во временной папке внутри `.file-organizer/`). По результатам выставляются возможности (4.9).

### 4.2. Листинг (`list`)
- Собственный обход папок (`Directory.list(followLinks: false)` по одной папке), без рекурсивного обхода `dart:io`.
- **Порядок:** лексикографический по сегментам пути (по кодовым единицам). Он стабилен и совпадает с обходом в глубину по отсортированным именам.
- **Курсор** — последний выданный логический путь. Возобновление — повторный обход с пропуском всего, что раньше курсора (целые поддеревья отсекаются).
- `skipFolder` вызывается для каждой папки до входа в неё.
- Не попадают в листинг: символические ссылки и junction-точки, сокеты, FIFO, устройства, облачные заглушки (1.6). Ярлыки Windows (`.lnk`) — обычные файлы и листингом не пропускаются.
- В «недоступные» (`inaccessible`) попадают: папки без доступа, папки-ссылки, папки на другом томе.
- Определение другого тома: Linux — `/proc/self/mountinfo` при открытии источника; Windows — точки монтирования являются reparse-точками (как ссылки); macOS — список точек монтирования (`getfsstat`) при открытии (в том числе подключённые образы `.dmg` и папки iCloud / сетевых дисков в `/Volumes`).
- Страница — до 500 файлов; `capturedAt` — из EXIF для JPEG (1.8).

### 4.3. Перемещение и восстановление без перезаписи
- `move(from, to)` и `restore(ref, to)` — только через `noReplaceRename` (FFI, 1.2):
  - Linux: `renameat2(AT_FDCWD, from, AT_FDCWD, to, RENAME_NOREPLACE)`; `EEXIST` → `targetExists`; `EXDEV` → `ioError` («другой том»); `EINVAL` / `ENOSYS` (ФС не поддерживает) → источник без `canMove`.
  - macOS: `renamex_np(from, to, RENAME_EXCL)`.
  - Windows: `MoveFileExW(from, to, 0)` — без флагов перезаписи и копирования; `ERROR_ALREADY_EXISTS` / `ERROR_FILE_EXISTS` → `targetExists`; `ERROR_NOT_SAME_DEVICE` → `ioError`.
- Перемещаются только файлы; дата изменения при переименовании сохраняется.
- `File.rename` из `dart:io` **запрещён** в адаптере (он перезаписывает цель); это проверяет тест исходного кода адаптера.

### 4.4. Папки
- `mkdir` создаёт одну папку: родитель должен существовать; если путь занят — `targetExists`. `Directory.create` молча проходит по существующей папке, поэтому создание идёт через FFI (`mkdir` / `CreateDirectoryW`), которые отказывают, если путь занят.
- `removeEmptyDir` — только пустую папку (системный вызов `rmdir` / `RemoveDirectoryW` сам отказывает для непустой).

### 4.5. Карантин (1.5)
- Папка `<корень>/.file-organizer/quarantine/<sessionId>/<n>` — сам файл, рядом `<n>.json` с исходным логическим путём, размером, датой изменения и временем помещения.
- `QuarantineRef` — `<sessionId>/<n>`; при разборе ссылка проверяется по шаблону (никаких `..` и разделителей сверх ожидаемых).
- `quarantine` — `noReplaceRename` файла в карантин, затем запись `<n>.json`. При падении между ними `findQuarantined` всё равно найдёт объект (по содержимому папки сессии и описаниям), а «осиротевший» объект без описания показывается в отчёте карантина.
- `findQuarantined(sessionId, path)` — поиск по описаниям в папке сессии.
- `purgeQuarantined` — **единственное удаление**: файл `<n>` и его описание, затем пустая папка сессии. Любой путь вне `.file-organizer/quarantine/` — отказ.
- `appFolders` = `{.file-organizer}`. Windows: у папки ставится атрибут «скрытый».

### 4.6. Хеширование
- Отдельный рабочий изолят с очередью задач; чтение блоками по 1 МБ; отмена через `CancelToken` между блоками (3.4).
- `partialHash` — размер и первые / последние 64 КБ; `fullHash` — весь файл. SHA-256, префикс `sha256:` (1.9).
- Облачные заглушки (Windows: атрибуты `RECALL_ON_DATA_ACCESS` / `OFFLINE`; macOS: флаг `SF_DATALESS` у файлов iCloud Drive и File Provider) не читаются → `unsupported` (файл просто не участвует в поиске дублей).

### 4.7. Ошибки ОС → `FileErrorKind`

| ОС | Код | Вид |
|---|---|---|
| POSIX | `ENOENT`, `ENOTDIR` (родитель — файл) | `notFound` / `wrongType` |
| POSIX | `EACCES`, `EPERM`, `EROFS` | `permissionDenied` |
| POSIX | `EEXIST` | `targetExists` |
| POSIX | `ENOTEMPTY` | `notEmpty` |
| POSIX | `EXDEV` | `ioError` (другой том) |
| Windows | 2, 3 (`FILE/PATH_NOT_FOUND`) | `notFound` |
| Windows | 5 (`ACCESS_DENIED`) | `permissionDenied` |
| Windows | 32, 33 (`SHARING/LOCK_VIOLATION`) | `locked` |
| Windows | 80, 183 (`FILE/ALREADY_EXISTS`) | `targetExists` |
| Windows | 145 (`DIR_NOT_EMPTY`) | `notEmpty` |
| Windows | 17 (`NOT_SAME_DEVICE`) | `ioError` |
| любая | прочее | `ioError` с текстом ОС |

### 4.8. Даты
- `FileStat.modified` возвращает местное время с микросекундами — адаптер приводит его к UTC. Точность зависит от ФС (FAT — 2 секунды), но повторное чтение даёт то же значение, а отпечатки сравниваются с тем, что прочитано раньше.

### 4.9. Возможности
`canMove`, `canMkdir`, `canQuarantine`, `quarantineRestorable` — если корень доступен на запись и проба переименования без перезаписи прошла; `providesCapturedAt` — да (JPEG, 1.8); `canAddToAlbum` и `systemPurgesQuarantine` — нет. Источник «только для чтения» сканируется, но план для него пуст (ядро это уже умеет).

### 4.10. Тесты адаптера
- **Контрактные тесты `FileSource`** (`test/contracts/file_source_contract.dart`) против адаптера на временных папках — Linux, Windows и macOS в CI.
- Специфика desktop: запрет `File.rename` в коде адаптера; macOS — нормализация Unicode (имя в NFC и NFD), ФС без учёта регистра (APFS), отказ в доступе TCC; перемещение и восстановление на занятую цель (в том числе цель, появившуюся между планированием и выполнением) — файл цели не тронут; ссылки и папки-ссылки не обходятся и не перемещаются; другой том (Linux: через подменённый список точек монтирования); заблокированный файл и длинные пути (Windows CI); таблица ошибок 4.7; курсор и возобновление на реальном дереве; карантин: описание, поиск, «осиротевший» объект, отказ очистки вне карантина; отмена хеширования большого файла; EXIF.

## 5. Платформенные службы (`lib/platform/`)

### 5.1. Часы и идентификаторы
- `SystemClock` — `DateTime.now().toUtc()`.
- `RandomIdGenerator` — UUID v4 на `Random.secure()` (без зависимости `uuid`).

### 5.2. База данных
- Файл `app.sqlite` в папке поддержки приложения (`drift_flutter`, `driftDatabase`). Миграции — по `schemaVersion` (3.5).

### 5.3. Один экземпляр
- При запуске приложение берёт эксклюзивную блокировку файла `app.lock` в папке поддержки приложения. Если не удалось — второй экземпляр показывает «приложение уже запущено» и не создаёт workflow.

### 5.4. Фабрика источников
- `FileSource? Function(SourceId)` для `CleanupWorkflow`: по `Source.location` открывает `DesktopFileSource`; если папки нет (диск отключён) — `null` (workflow сообщит «недоступен»).

## 6. Слой состояния (`lib/state/`, Riverpod)

- Провайдеры: база, репозитории, фабрика источников, `CleanupWorkflow` (живёт всё время работы приложения), поток состояний workflow, список источников, история сессий (с журналом), настройки.
- При запуске: блокировка экземпляра (5.3) → открытие БД → `workflow.initialize()` (восстановление и очистка карантина).
- Изменения данных из UI — только через уведомители (notifier) слоя состояния: добавление источника (с проверкой вложенности 1.10 и сетевого диска 1.6), пометки зон, правила, настройки.
- Закрытие окна во время выполнения или отката — диалог подтверждения; если приложение всё-таки закрыто или упало — при следующем запуске работает `recovery`.

## 8. UI (`lib/ui/`)

Material 3, раскладка для окна компьютера. Экраны:

1. **Онбординг** (первый запуск): что делает приложение и почему это безопасно (план до выполнения, карантин вместо удаления, откат); выбор папок-источников (`file_selector`); подтверждение названий папок шаблона.
2. **Главный экран:** большая кнопка «Навести порядок»; итоги последней уборки; список источников с состоянием (доступен / недоступен).
3. **Прогресс:** этапы (скан, анализ, выполнение, откат) по источникам, счётчики, кнопка «Отменить».
4. **План:**
   - группы с галочками: «Дубли: N файлов, X ГБ», «В Документы: N», «В Фото / 2024: N»;
   - раскрытие группы — файлы с причинами; отдельные файлы можно снять;
   - «Не разобрано: N» и «Ещё N копий в ваших папках — не трогаем» — только информация;
   - предупреждения: недоступные источники и папки, файлы, которые не удалось захешировать;
   - сводка одобренного; кнопки «Применить» и «Отказаться».
5. **Результат:** выполнено / пропущено / ошибок с причинами («требует внимания» выделено); кнопка «Отменить уборку».
6. **Прерванная уборка** (при запуске): что было восстановлено; «Доделать» или «Откатить».
7. **История:** сессии со статусами и датами; откат всей сессии, группы или отдельного файла; отметка «карантин очищен — откат невозможен».
8. **Настройки:** источники (добавить, выключить, удалить из списка — файлы не трогаются); пометки зон (папка: «убирать», «не трогать», «исключить»); пользовательские правила классификации; срок карантина; язык интерфейса.

Тесты UI — виджет-тесты на фейковом workflow: каждый экран по каждому состоянию, одобрение, отмена, недопустимые действия недоступны.

## 10. Архитектурные правила (расширение архитектурного теста)

| Слой | Может импортировать |
|---|---|
| `core` | только Dart SDK (без `dart:io`) и разрешённые чистые пакеты (без изменений) |
| `data` | `core`, drift |
| `platform` | `core`, `dart:io`, `dart:ffi`, `dart:isolate`, разрешённые пакеты платформы |
| `state` | `core`, `data`, `platform`, Riverpod |
| `ui` | `core/model`, `state`, Flutter; **не** `data` и не `platform` |

В адаптере запрещены `File.rename`, `Directory.rename`, `delete` вне `purgeQuarantined` / `removeEmptyDir` — проверяется тестом исходного кода `lib/platform/desktop/`.

## 14. Риски этапа

- **Перезапись на уровне ОС.** Главный риск этапа; закрывается решением 1.2 и тестом, запрещающим `File.rename` в адаптере.
- **Облачные папки** (OneDrive часто синхронизирует Рабочий стол и Документы на Windows): перемещение внутри них синхронизируется, но чтение заглушек скачивает файлы — решение 1.6.
- **Антивирусы** могут временно блокировать файлы — это ошибка `locked`, операция не выполняется, уборка продолжается.
- **Нормализация Unicode на macOS** (одно имя в NFC и NFD): возможен ложный конфликт имён, но не перезапись — переименование без перезаписи откажет.
- **Запросы доступа macOS (TCC):** первое обращение к «Рабочему столу», «Документам», «Загрузкам» показывает системный запрос; отказ — `permissionDenied`, UI объясняет, как дать доступ.
- **Неподписанные сборки на macOS:** Gatekeeper предупреждает при запуске (подпись и нотаризация — этап 5).
- **Неподписанные сборки:** предупреждение SmartScreen на Windows (подпись — этап 5).
- **Производительность** на больших папках — проверяется нагрузочным тестом (задача 16).
